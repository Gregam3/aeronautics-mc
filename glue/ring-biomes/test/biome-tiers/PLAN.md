# Biome-tier verification harness

**Purpose:** the in-game gate the JUnit suite can't cover. JUnit tests prove the
pure-Kotlin `resolveTier` math is correct in isolation; this harness proves the
codec parses our dimension JSON, `VoronoiTieredBiomeSource` actually drives the
overworld at runtime, the tier tags resolve, and substitution lands a
tier-appropriate biome at every sample point.

## What it does

1. Boots a NeoForge 1.21.1 dedicated server staged in `/tmp/aero-audit-server`
   (reuses `../ore-density/scripts/bootstrap-server.sh`).
2. Stages mods + configs from the running PrismLauncher instance, with
   client-only mods filtered out.
3. Writes a deterministic `server.properties` (fixed seed, peaceful).
4. Waits for the `Done (...)` boot line, capturing the
   `caero_rings DIAG: medium_min=... hard_min=... floor_jitter=... seeds=...`
   line if it lands during boot. (If the biome source never emits its DIAG
   line, the codec didn't bind — the verify run reports that prominently.)
5. `/forceload add` for each sample chunk. Waits ~20 s for chunk gen to settle.
6. For each sample point, sends three queries:
   ```
   /execute if biome <x> 64 <z> #caero_rings:tier_easy   run say BIOMETIER_<id>_easy
   /execute if biome <x> 64 <z> #caero_rings:tier_medium run say BIOMETIER_<id>_medium
   /execute if biome <x> 64 <z> #caero_rings:tier_hard   run say BIOMETIER_<id>_hard
   ```
   Only the matching tier's `say` actually runs, so its marker shows up in
   the log. Greps the markers out, tallies which tier each point landed in.
7. Asserts the observed tier matches the prediction from
   `VoronoiTieredBiomeSource.resolveTier()` (i.e. what the JUnit tests cover).

## What can go wrong vs. what it catches

| Failure mode | Caught by JUnit | Caught here |
|---|---|---|
| Math wrong (Voronoi or floor logic) | yes | yes (redundant) |
| Codec field missing from JSON | no — JSON isn't parsed | yes (boot fails or DIAG missing) |
| Tier tag not bound (HolderSet empty) | no | yes (substitution falls through, reports `OCEAN/UNTAGGED`) |
| Biome source not registered as Voronoi-tiered | no | yes (every point reports the natural multi_noise biome's tier, mismatching prediction) |
| Substitution drops oceans/rivers correctly | no | partial — sample points stay over land, but mismatches will be reported |

## Sample points

Twelve hand-picked (x, z) coordinates that exercise:
- Spawn lock + inner easy core (4 points, expected easy)
- First medium ring just outside `medium_min_radius` (2 points, expected medium)
- Inner-hard intrusion at r ≈ 3000 (1 point, expected hard)
- Outer-medium pockets at r ≈ 4000 (2 points, expected medium)
- Far-edge hard (3 points, expected hard)

When the seed list or floor parameters change, edit `SAMPLE_POINTS` in
`scripts/verify.py` accordingly. The JUnit suite has parameterized tests over
the same constellation; keep them consistent.

## Caveats

- A point can legitimately land on an ocean / river / unclassified biome the
  natural `multi_noise` produced. The harness reports those as
  `OCEAN/UNTAGGED` and doesn't count them as failures, since the biome source
  intentionally passes those through untouched.
- Boot is slow with the full mod stack (~2–4 minutes cold). `--boot-timeout`
  defaults to 240 s; raise it if a heavier mod gets added.
- `/forceload` only generates chunks once per slot; running this harness
  twice in a row without resetting the world will use the chunks generated by
  the first run. The driver wipes `audit-world` at the start by default.
